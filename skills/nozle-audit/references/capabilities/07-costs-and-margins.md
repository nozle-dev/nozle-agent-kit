# 7. Track costs and margins

**Covers:** provider costs, Cost Sheets, and reporting.
**Account needs:** `cost_models` (Cost Sheets; a missing or unpublished sheet is a manual dashboard step); `margin_policies` shows enforcement if configured.
**Shared prerequisites:** `usage_attribution`, `server_key`.

**Decide with the user**
- `cost-only-vs-billable`: for each provider call, is it cost-only tracking, billable usage, or untouched? (Never assume "free" means cost-only.)
- `cost-attribution`: which customer or feature a provider cost belongs to.

**Implement**
- `wrapOpenAI` and `wrapAnthropic` patch a client instance and emit one Feature Event when usage is present; `costMeterCode` adds detailed Cost Events. Inspect shared clients and every caller first, because a wrapper can emit billable usage for free callers. A wrapper always emits a billable Feature Event, so cost-only tracking cannot use one: send Cost Events (`POST /cost-events` with `cost_meter_code`, `external_customer_id` or `parent_transaction_id`, a stable `cost_event_id`, token `properties` and a Unix-seconds `timestamp`). Use the SDK method: Node `nozle.costEvents.track({...})`, Python `nozle.cost_events.track(...)` (both Engine host, `timestamp` as a number of Unix seconds), Go `TrackCostEvent`; REST from any other language. Cost Events never bill the customer. See runtime-contracts.md. Source: https://docs.nozle.dev/sdks/node/llm-auto-capture.md
- Never emit the same consumption twice (wrapper plus a manual call).
- **Generic capture** covers most other clients: Node 0.13+ `nozle.captureFetch({ customerId, featureCode?, costMeterCode?, onError })` passed as the client's `fetch` (OpenAI or Anthropic SDK, Vercel AI SDK providers, LangChain, raw `fetch`, any OpenAI-compatible API, Gemini); Python 0.13+ `nozle.wrap_http_client(client, customer_id=...)`, `nozle.capture_http_client(...)` or `capture_async_http_client(...)` for httpx clients (`pip install 'nozle-sdk[httpx]'`); Go v0.12+ `WrapHTTPClient(httpClient, nozle, CaptureOptions{...})`. It sends the same Feature Event and Cost Events as the wrappers, keyed by the provider response id, so a manual `track` for the same call bills twice. Choose the customer per request (`customerId` as a function, or the `X-Nozle-Customer-Id` request header, which is not forwarded); a request with no customer records nothing, which keeps free callers unbilled. It takes no subscription id, so the customer needs exactly one active subscription. Wire `onError`: `feature_not_found` means the usage is stored but not billed until a metered Feature with that code exists, so that Feature is a setup step. Code that reads usage itself sends it with `recordUsage` / `record_usage` / `RecordUsage`. Python LiteLLM: captured only when LiteLLM's HTTP client is Nozle's (`litellm.client_session = nozle.capture_http_client(...)` covers the OpenAI and Azure providers; other providers need a wrapped client per call; Bedrock usage is not recognised).
- **Without capture** (other languages, clients that take no custom `fetch` or HTTP client, Bedrock, responses without a recognised usage shape, or when the user wants durable queued delivery) track the same data manually; nothing is lost. After each provider call, read the provider's reported usage (for a stream, the final usage chunk; with OpenAI-compatible clients and LiteLLM set `stream_options={"include_usage": True}`). Then send the usage: `usage.track` alone when the action spends credits, otherwise `track()` after success with `provider`, `model`, `input_tokens`, `output_tokens` properties, a key from the message or request id and a fixed timestamp. Then send one Cost Event per non-zero token type (`POST /cost-events` with `cost_meter_code`, `parent_transaction_id` set to the usage event's transaction id, a stable `cost_event_id`, and `properties: { tokens, provider, model, type }`). The model name must match a Cost Sheet rate, or the cost lands in the Uncosted queue. Unlike the wrappers, this path can retry from a queue.
- Margin reads (`/margin/*`) honour only `from` and `to`; other filters are ignored, so filter the result yourself. A bad `granularity` returns 400 `invalid_granularity`.
- Use only cost meter codes and rates that exist in the Cost Sheet read. Unknown rates stay uncosted; cost processing is asynchronous, so figures can lag.

**Verify (local only):** a mock shows the cost event for an approved call, nothing for excluded callers, and no duplicate with the usage event.

**Do not:** invent rates, double count shared costs, or present delayed figures as final.
